# 流光下载器功能路线图

文档状态：五个阶段已完成，等待后续发版

## 目标

继续保持“下载 HLS 或 MP4 并输出本地 MP4”的定位，优先提高下载前的可预期性、任务可靠性和资源兼容范围。不增加内置播放器、实时通知进度、手动清晰度选择或请求头配置。

## 实施顺序

### 1. 下载前检查（已完成）

- 创建任务前检查目标存储空间。
- MP4 直链通过响应长度读取预计文件大小；HLS 按分片时长与播放流码率估算大小。
- 预检阶段识别不支持的 HLS 格式，避免任务入队后才失败。
- 检查目标目录是否存在同名文件；默认采用自动重命名（`名称 (1).mp4`），不覆盖已有文件。
- 在创建弹框中展示预计大小、剩余空间和文件名处理结果；空间明显不足时禁止开始。

### 2. 任务恢复（已完成）

- 进程被系统回收、应用重新启动或设备重启后，恢复任务记录和缓存状态。
- 将中断中的任务统一标记为可继续，保留已完成 HLS 分片和 MP4 Range 临时文件。
- 网络恢复只提示用户继续，不未经确认自动消耗移动流量。
- 评估前台服务启动时的持久队列恢复，避免仅恢复 UI 记录。

### 3. 批量任务（已完成）

- 支持流光一次传递多条下载地址和对应文件名。
- 批量确认时统一选择保存目录，并显示任务数量和重复文件名处理结果。
- 单条任务继续复用现有暂停、继续、重试和删除能力。
- 对接协议优先增加 `items` JSON extra，保留现有单条 deep link 兼容性。

### 4. 错误与重试（已完成）

- 将网络中断、链接过期、HTTP 401/403、空间不足、格式不支持和合并失败分开显示。
- 对可恢复错误提供有限次数的指数退避重试；链接或权限错误直接提示用户修正来源。
- 保留失败原因和最近一次失败时间，重试时继续使用已有断点缓存。

### 5. HLS 兼容性（已完成）

- 支持 fMP4 初始化片段（`#EXT-X-MAP`）并扩展合并管线。
- 支持 `BYTERANGE` 分片及其偏移、长度校验。
- 对含 `EXT-X-DISCONTINUITY` 的 fMP4 播放列表明确拒绝，避免跨 period 静默拼接。
- 增加对应解析、断点和合并测试。
- DRM、Widevine、FairPlay、SAMPLE-AES 不在范围内。

## 当前验收结果

- 解析单测覆盖 AES-128、fMP4 MAP、显式/隐式 BYTERANGE、非法偏移、Range 响应与断点缓存判定。
- Redmi Note 8 Pro 真机完成 3 分片 fMP4 和 3 段 BYTERANGE 下载，产物音频、视频均可完整解码。
- 使用三条真实 AES-128 TS-HLS 资源完成批量回归，3 个任务全部成功，失败计数未增加。

## 阶段验收

每个阶段完成后执行相关单元测试、debug 构建；涉及下载链路时使用真实 MP4 与 HLS 地址在连接设备上验收。发布前再执行正式签名构建、APK 校验和 Release 资产回验。
